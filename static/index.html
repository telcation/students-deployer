提出・再デプロイ 完全ガイド

このページは、提出前の確認から再デプロイ・トラブル対応まで、
学生が必要なすべての情報を一か所にまとめたユーザーズマニュアルです。
迷ったら、目次から必要な項目を開いてください。

⚠ 重要：「ローカルで動く」＝「サーバーで動く」ではありません。 サーバーは /種別/学期/学生番号/アプリ名/ の深いパスで動きます。提出前チェックを必ず確認してください。

提出前チェックリスト（全員必須）

提出直前の最終確認です。チェック漏れがあると、ほぼ確実に失敗します。必ず上から順番に確認してください。
全員必須（最優先）
提出前チェックリスト（総合）
  • 提出物のファイル名が指定のルールに沿っている
  • 言語・バージョン申請と、実際に使用したバージョンが一致している
  • ローカルで 最終動作確認 を完了している
  • 不要なファイル（venv/、node_modules/、target/ など）が含まれていない
  • 提出するファイルは最新のものである（古いzipを提出していない）
  • アプリ名に記号・スペースが含まれていない（英数字・アンダースコアのみ）
💡 提出後は、しばらく待ってからデプロイ結果のログを確認しましょう。エラーがある場合はログに理由が書かれています。

Python アプリ提出用 zip 作成手順（Windows / PyCharm）

Python
zip 構成・requirements.txt・venv 除外

zip ファイルの内部構成・requirements.txt の書き方・venv の除外方法を確認します。

1
requirements.txt を作成する
PyCharm 下部の「ターミナル」タブを開き、仮想環境が有効な状態で実行：
pip freeze | Out-File -Encoding utf8 requirements.txt
生成されたファイルをプロジェクトビューで開いて内容を確認する（空の場合はライブラリを追記）。
2
venv フォルダを除外する
venv/、.venv/ フォルダはzipに含めない。
PyCharm のプロジェクトビューで venv フォルダを除いたファイル群を選択し、 エクスプローラーで右クリック圧縮するか、ターミナルで zip コマンドを使って作成する。
3
zip の内部構成を確認する
zip を開いたとき、直下に app.py と requirements.txt が見えている こと。フォルダが二重になっていないか確認する。
⚠ NG例：myapp.zip を開いたら myapp/ フォルダが入っていて、その中に app.py がある → 二重構造。要修正。
4
ファイル名のルールを確認する
ファイル名は英数字・アンダースコアのみ。日本語・スペース・記号は使わない。
例：myapp_flask.zip ✅　　マイアプリ 最終版.zip ❌

Spring Boot 提出用 jar 作成手順（Windows / IntelliJ）

Java（Spring Boot）
bootJar / package、jar起動確認、ファイル名ルール

IntelliJ IDEA で実行可能 jar（bootJar）を作成し、ローカル起動を確認してから提出します。

1
build.gradle / pom.xml を確認する
Gradle の場合：bootJar タスクが有効になっているか確認。
Maven の場合：spring-boot-maven-plugin が pom.xml に含まれているか確認。
2
jar をビルドする
Gradle：右ペインの「Gradle」→「Tasks」→「build」→bootJar をダブルクリック
Maven：右ペインの「Maven」→「Lifecycle」→package をダブルクリック
ビルド後、build/libs/（Gradle）または target/（Maven）に jar が生成される。
3
ローカルでの jar 起動確認
ターミナルで以下を実行し、ブラウザで動作を確認する：
java -jar build/libs/アプリ名-0.0.1-SNAPSHOT.jar
⚠ 絶対パスを使っていないか確認。 new File("C:/Users/...") や "/home/user/..." はサーバーで動きません。
4
ファイル名ルールを確認して提出
jar ファイルを提出。ファイル名は英数字・アンダースコアのみ。
バージョン申請と一致した Java バージョンでビルドしたことを確認する。
Java 最終確認
Spring Boot 提出前チェックリスト
  • application.properties に server.port の ハードコードがない（サーバー側が指定）
  • ファイルパスに絶対パス（C:\ や /home/）が使われていない
  • Thymeleaf テンプレートに th:href / th:action / th:src を使っている
  • build/libs/（Gradle）または target/（Maven）内の jar を提出している
  • ローカルで java -jar 実行後、ブラウザで動作確認済み
  • バージョン申請（Java 17 / 21 / 25）と、ビルドに使った JDK が一致している

Flask（DB使用）アプリ 提出前チェックリスト

Python（Flask + DB）
db.create_all() の場所・DBパス固定・url_for・初回500対策
  • db.create_all() がアプリ起動時に必ず実行されるようになっている
  • DBのパスが 絶対パス固定でなく、起動ディレクトリ基準（os.path.dirname(__file__) など）になっている
  • テンプレート内のリンクが url_for() を使っている（ハードコードのURLでない）
  • 初回アクセス時に DB が存在しなくても 500 にならないよう、エラーハンドリングがある
  • requirements.txt に Flask、SQLAlchemy 等すべての依存が記載されている
  • debug=True が本番（提出用）コードに残っていない
🚨 DBファイルのパスが絶対パスになっていると、サーバー環境で起動に失敗します。 SQLALCHEMY_DATABASE_URI = 'sqlite:////home/user/data.db' のような記述は要修正。

Streamlit アプリ 提出前チェックリスト

Python（Streamlit）
Streamlit 固有のルールと注意点

Streamlit は Flask と異なる起動方式のため、専用のルールがあります。 Flask のチェックリストと合わせて確認してください。

  • 提出ファイルは 必ず zip 形式（単独の .py ファイルは非対応）
  • メインファイル名は app.py 固定（他のファイル名は起動されない）
  • requirements.txt に streamlit 以外の依存ライブラリもすべて記載されている
    ※ streamlit 本体はサーバーが自動インストールするが、他のライブラリは requirements.txt が必要
  • zip の直下に app.py と requirements.txt が見えている（二重フォルダになっていない）
  • ページ内リンク・画像パスを 絶対パスでハードコードしていない
  • st.set_page_config() を使う場合、スクリプトの 最初に呼んでいる
⚠
URLパス（baseUrlPath）について
Streamlit アプリは以下のURLパスで公開されます：
/f/学期/学生番号/アプリ名/

サーバーが --server.baseUrlPath を自動設定するため、学生側での設定は不要です。
ただし、アプリ内で st.page_link() などを使う場合はパスに注意してください。

🚨 単ファイル（.py）のアップロードは非対応です。 必ず zip にまとめてから提出してください。
zip の中に app.py が直接入っている構造が正解です。
Streamlit zip 構成例
正しい zip 構成
myapp.zip ├── app.py ← メインファイル（名前は必ず app.py） ├── requirements.txt ├── pages/ ← マルチページの場合（任意） │ └── page2.py └── assets/ ← 画像など静的ファイル（任意）
❌ NG：myapp.zip → myapp/ → app.py （二重フォルダ） ❌ NG：myapp.zip → main.py （ファイル名が app.py でない） ❌ NG：app.py を直接アップロード （zip にしていない）
⚠

注意事項：リンク指定の注意（相対パス問題）

サーバーはアプリを 深いURLパス で公開します。ローカルのルートパスと異なるため、相対パスのリンクが壊れやすいです。
超重要（Spring Boot）
Thymeleaf の th:href / th:action / th:src を使う

Spring Boot + Thymeleaf の場合、リンクはすべて Thymeleaf の属性で指定してください。

❌ NG例（相対パスが壊れる）

<a href="/home">トップへ</a> <form action="/submit"> <img src="/static/logo.png">

✅ OK例（Thymeleaf を使う）

<a th:href="@{/home}">トップへ</a> <form th:action="@{/submit}"> <img th:src="@{/static/logo.png}">

サーバー上のURLパス構造：

/種別/学期/学生番号/アプリ名/

例：/flask/2601/26010001/myapp/ のような深いパスになります。
href="/home" は https://telcation.f5.si/home を指してしまい、ルートに飛びます。

💡 Flask の場合は url_for('ルート名')、静的ファイルの場合は url_for('static', filename='...') を使ってください。

よくあるNG例（失敗例・地雷集）

過去に多くの学生が引っかかった失敗パターンです。提出前に必ず確認してください。
NG①：venv フォルダごと提出している
venv/ は数百MBあり、アップロードに失敗するか、デプロイが壊れます。 必ず除外してから zip を作成してください。
NG②：requirements.txt がない、または空
サーバーはライブラリをインストールできず、ModuleNotFoundError になります。 pip freeze | Out-File -Encoding utf8 requirements.txt で生成し、中身を確認してください。
NG③：ビルド成果物（target/, build/classes/ など）を含めた zip を提出している
Java の場合、提出するのは jar ファイルのみ。ソース一式を zip にする場合は target/ を除外。
NG④：申請バージョンと実際のバージョンが違う
Python 3.12 で申請したのに 3.13 で開発した、など。UnsupportedClassVersionError の原因になります。
NG⑤：絶対パスのハードコード
C:\Users\YamadaTaro\... はサーバーに存在しません。os.path.dirname(__file__) や Path(__file__).parent で相対パスを使ってください。
NG⑥：zip が二重フォルダ構造になっている
myapp.zip → myapp/ → app.py の構造は NG。 myapp.zip → app.py （直下にファイルが見える）が正しい構造です。
NG⑦：Streamlit で .py ファイルを直接アップロードしている
Streamlit は zip 形式のみ対応です。app.py を直接アップロードしてもデプロイできません。 必ず zip にまとめて提出してください。
NG⑧：Streamlit のメインファイル名が app.py でない
サーバーは app.py を固定で起動します。main.py・streamlit_app.py など別名のファイルは起動されません。
NG⑨：講師の指示なしで何度も再デプロイする
サーバーに負荷がかかります。再デプロイは講師から指示があった場合のみ実施してください。

Python / Java バージョン申請ルール

ルール
申請バージョンと開発バージョンは必ず一致させる

デプロイシステムは申請されたバージョンを使用してアプリを起動します。 実際に開発したバージョンと異なると、起動に失敗します。

対応バージョン一覧

言語 対応バージョン 確認方法
Python 3.12　3.13　3.14 python --version
Java 17　21　25 java --version
ビルドツール gradle　maven build.gradle / pom.xml で確認
🚨 申請と異なるバージョンでビルドした場合、UnsupportedClassVersionError（Java） や 構文エラー（Python） でデプロイ失敗します。

トラブル対応：ログの読み方

デプロイに失敗したとき、ログに 原因が書かれています。 最後まで読んでください。途中でやめない。
基本
ログを読む3つのポイント
1
最後まで読む
エラーは最後の方に出ることが多いです。途中で止まらず最後まで確認。
2
ERROR / FAILED / Exception を探す
これらのキーワードが含まれる行が原因です。
3
解決できない場合はログをそのまま講師に貼る
「エラーになりました」だけでは原因が分かりません。ログ全文をコピーして貼り付けてください。

よくあるエラーと対処法

Python エラー
ModuleNotFoundError: No module named 'xxx'

ライブラリのインストールに失敗しています。

Installing requirements... ERROR: ModuleNotFoundError: No module named 'flask'
✅ 対処：requirements.txt に flask が記載されているか確認。記載されていない場合は追記して再提出。
Java エラー
UnsupportedClassVersionError

ビルドに使った Java バージョンが、申請バージョンと異なります。

java.lang.UnsupportedClassVersionError: Unsupported major.minor version 65.0
✅ 対処：申請したバージョン（例：Java 21）で再ビルドして提出し直す。
共通エラー
404 Not Found / ページが表示されない

URLパスの設定が間違っているか、リンクが相対パスになっています。

✅ 対処（Spring Boot）：Thymeleaf の th:href="@{/パス}" を使っているか確認。
対処（Flask）：url_for('ルート名') を使っているか確認。
Flask + DB エラー
Internal Server Error (500) — 起動直後

DBファイルが存在しない、またはパスが間違っています。

✅ 対処：db.create_all() がアプリ起動時（app.app_context() 内）に呼ばれているか確認。 DBパスに絶対パスを使っていないか確認。
